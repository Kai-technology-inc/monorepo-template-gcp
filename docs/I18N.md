# Languages (i18n)

Every text a person reads in the web comes from `@app/i18n` (`packages/i18n`). The template ships English (`en`, the
base), Spanish (`es`) and Portuguese (`pt`).

## How it fits together

```text
packages/contracts/src/locale.ts        SUPPORTED_LOCALES, DEFAULT_LOCALE, negotiateLocale()
packages/i18n/src/messages/en.ts        the base dictionary (as const): keys and placeholders are typed from it
packages/i18n/src/messages/es.ts, pt.ts typed as Messages: a missing or extra key does not compile
packages/i18n/src/translator.ts         createTranslator(locale, messages) → t(key, params)
packages/i18n/src/formatters.ts         dates, numbers, currency, relative time, lists (Intl)
packages/i18n/src/react.tsx             <I18nProvider>, useT(), useFormatters(), <RichText>
apps/web/src/i18n/server.ts             getLocale() and getI18n() for server components
```

**Choosing the language**, in order:

1. The signed-in person's profile (`users/{uid}.locale`), which they change in Settings. After sign-in the web
   copies it into the cookie, so the next server render already speaks it.
2. The `app-locale` cookie (`LOCALE_COOKIE`), set by the language picker even when signed out.
3. The browser's `Accept-Language` header (`negotiateLocale`: `es-AR` → `es`).
4. `DEFAULT_LOCALE` (`en`).

The root layout loads only that language's dictionary and passes it to `<I18nProvider>`: a page never ships the
other languages. Firebase Auth's own emails (verification, password reset) follow it too
(`auth.languageCode`).

## Writing text

```tsx
const t = useT();
<h1>{t('members.title')}</h1>
<p>{t('members.subtitle', { workspace: session.workspace.name })}</p>
<p>{t('members.count', { count: members.length })}</p>              // plural
<RichText k="auth.login.noAccount" tags={{ link: (c) => <Link href="/auth/register">{c}</Link> }} />
```

```ts
// server component
const { t, format } = await getI18n();
format.date(member.joinedAt); // "Mar 5, 2026" / "5 mar 2026"
```

Rules:

- **Keys are grouped by screen or feature**, not by word (`auth.login.title`, `members.invite.submit`). The same
  English word in two places is two keys: they may translate differently.
- **Placeholders are `{camelCase}`** and are type-checked: `t('dashboard.welcome')` without `{ name }` does not
  compile.
- **Plurals** are objects with CLDR categories: `{ one: '{count} member', other: '{count} members' }`, plus `zero`
  when "No members yet" reads better than "0 members". Each language uses the categories it needs (Polish adds
  `few`/`many`). The selection uses `Intl.PluralRules`. Never name a namespace key `other`: it marks a plural.
- **Markup** for links or emphasis inside a sentence is `<tag>…</tag>` in the message and a renderer in
  `<RichText tags>`. Attributes (hrefs, classes) belong to the code, words to the dictionary.
- **Numbers and dates** go through `useFormatters()` / `format`, never `toLocaleString()` without a locale or a
  hand-built `dd/mm/yyyy`.
- **API errors** are translated from their code: `errors.<CODE>`. Adding a code to `ERROR_CODES` without its
  message in every language fails the build.
- **No hardcoded text in JSX**: ESLint's `react/jsx-no-literals` is on for every web package. Punctuation is allowed.
  If a string is truly not copy (a brand name), add it to `allowedStrings` in that package's `eslint.config.mjs` with
  the reason.

## What enforces it

| Check       | Where                                                 | Catches                                                                                                             |
| ----------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| TypeScript  | `Messages`, `MessageKey`, `ParamsOf` in `types.ts`    | unknown keys, missing params, a locale missing a key                                                                |
| Parity spec | `packages/i18n/src/messages/parity.spec.ts`           | placeholders or tags renamed in one language, empty strings, plurals without `other`, error codes without a message |
| ESLint      | `react/jsx-no-literals` via `@app/eslint-config/next` | text written directly in JSX                                                                                        |

## Adding a language

1. Add the code to `SUPPORTED_LOCALES` in `packages/contracts/src/locale.ts`.
2. Copy `packages/i18n/src/messages/es.ts` to `<code>.ts`, translate it and register its loader in
   `messages/index.ts`.
3. Add its native name to `LOCALE_NATIVE_NAMES` (and `rtl` in `directionOf` if it is written right to left).
4. `pnpm turbo run typecheck test --filter=@app/i18n`: the compiler and the parity spec list whatever is missing.

## Text in the API

The API stores each person's `locale` precisely so that server-generated content (emails, exports) can follow it.
The template's API sends no text, only error codes. When you add emails, keep their templates in a server-side
dictionary keyed by the same locales, and pass `user.locale`.
