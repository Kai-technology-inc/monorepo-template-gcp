# @app/web

The Next.js app (App Router) deployed to Firebase App Hosting. It holds **routes only**: each `page.tsx` renders a
screen from `@app/web-platform` (or your module's web package) in a few lines.

| Path                      | What                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `src/app/layout.tsx`      | the request's language decides `<html lang>` and the one dictionary sent to the browser                          |
| `src/app/(auth)/auth/*`   | login, register, forgot-password, verify-email, action (Firebase email links), invitations/accept                |
| `src/app/(app)/*`         | dashboard, members, settings: `AppShell` gates them (signed in, registered, verified when required, a workspace) |
| `src/app/health/route.ts` | static liveness for App Hosting and uptime checks                                                                |
| `src/i18n/server.ts`      | `getLocale()` / `getI18n()` for server components (cookie → `Accept-Language` → default)                         |
| `apphosting*.yaml`        | App Hosting config: base, plus `qa`/`prod` generated by `pnpm setup:gcp` (public values only)                    |

## Things App Hosting cares about

- It installs with `pnpm install --prod`: what `next build` needs goes in `dependencies`, not `devDependencies`.
- `next` has an explicit version here (never `catalog:`): App Hosting reads this field.
- The backend's environment name (`qa`, `prod`) picks `apphosting.<env>.yaml`; `pnpm setup:web <env>` sets it.

`src/lib/url-vocabulary.spec.ts` checks that route segments are English kebab-case. `AGENTS.md` in this folder is
written by `next dev` (Next's own guidance for agents); keep it committed.
